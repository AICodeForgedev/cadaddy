# Releasing CADaddy

The canonical recipe is craftrules' [`release/playbook.md`](https://github.com/storytold/craftrules/blob/main/release/playbook.md); this file covers only what's CADaddy-specific.

- **Version:** `[workspace.package] version` in the root `Cargo.toml` is the single source. `cargo xtask version` prints it; `cargo xtask version set X.Y.Z[-pre]` changes it. The app shows it in About, `cadaddy --version` and `cadaddy-cli --version`; release builds also embed the commit (`CADADDY_BUILD_SHA`).
- **Cut a release:** bump the version on `main`, then push `main` to `release` (`git push origin main:release`). Every push to `release` runs `.github/workflows/release.yml` and creates or updates the draft GitHub Release `CADaddy v<version>`. A `workflow_dispatch` run with `version: X.Y.Z-rc.N` makes a test build. A dispatch on any other branch is a dry run: the unsigned jobs (version, Linux, Linux riscv64, Flatpak, FreeBSD, web) build, the `release` environment refuses the signing jobs (macOS, Windows), and no release is drafted.
- **Artifacts:** macOS universal `.dmg` (Developer ID signed, notarized, stapled) and CLI `.zip`; Windows x64, x86 and arm64 `.msi` + portable `.zip` (Azure Trusted Signing); Linux x86_64 and aarch64 `.AppImage` (+ `.AppImage.zsync` for AppImageUpdate delta updates), `.flatpak` bundle (repackages the tarball, `packaging/linux/flatpak-bundle.sh`), `.deb`, `.rpm`, `.tar.gz` (+ the from-source Flathub manifest in `packaging/linux/flatpak/`); Linux riscv64 `.tar.gz` (cross-compiled on Ubuntu 24.04 against ports.ubuntu.com riscv64 libraries, CLI smoke-tested under QEMU); FreeBSD x86_64 `.tar.gz` (built in a FreeBSD VM); web `.zip` (wasm + `index.html`, see `packaging/web/README.md`); `SHA256SUMS.txt`.
- **Secrets:** the twelve signing secrets live in the `release` environment (deployable only from the `release` branch, which only org admins and release-managers can push). All are optional: a missing one produces unsigned artifacts with a warning.
- **Windows installer:** `packaging/windows/cadaddy.wxs` (WiX v5 + `WixToolset.UI.wixext`), per user (no administrator), publisher AICodeForge; registers CADaddy for .dwg/.dxf (default where the user has no choice yet, Open with, Settings > Default apps). Its wizard has a Shortcuts page: the Start Menu shortcut is always created, the desktop shortcut is opt-in (`DESKTOPSHORTCUT=1` for silent installs, `DESKTOPSHORTCUT=0` drops it on an upgrade; otherwise upgrades keep the previous choice).
- **File types:** `.dxf` and `.dwg` (macOS document types, Windows "Open with", Linux MIME types).
- **Local packaging test:** `packaging/macos/package.sh` (ad-hoc signed DMG), `packaging/linux/package.sh`, `packaging/web/package.sh`.
- **Update-gate (run before every release):** `cargo xtask update-gate --from <previous release installer> --to <new installer>` tests the real update path end-to-end on each OS. It installs the old release, serves the new one from a local fake GitHub feed (signed with a test key), launches the old app with default settings (agent control on, no `--control` scripting), overrides the update source via env vars (`CADADDY_UPDATE_GATE`, `CADADDY_UPDATE_API`, `CADADDY_UPDATE_DOWNLOADS`, `CADADDY_UPDATE_KEY`), confirms the update card is shown (`has_control_channel()=false`), triggers Update, waits for the download (verified by the app's real updater against the test key), triggers Restart Now, waits for the app to quit and the real `updater::install` to complete, then verifies the new version runs (`--version`), settings survived and temp is clean. On macOS: two `.dmg` files — the updater mounts the new DMG and swaps the `.app`. On Windows: two `.msi` files — the updater's PowerShell script runs `msiexec /passive`. On Linux: two AppImages — the updater renames the new one over the old. Each gate runs only on its own OS; mismatched types are an error (never a false pass). The gate catches 0.7.8's two bugs: `DETACHED_PROCESS` (PowerShell quit before running the MSI) and `has_control_channel()` returning true for the agent port alone (hiding the update card from default installs).
